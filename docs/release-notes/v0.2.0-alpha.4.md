> **Prerelease, not yet on the air.** The test plan: [BENCH.md](https://github.com/TechnikWeber/AXLink/blob/v0.2.0-alpha.4/docs/BENCH.md).

Since [v0.2.0-alpha.3](https://github.com/TechnikWeber/AXLink/releases/tag/v0.2.0-alpha.3): AXLink can be set up without the command line. Nothing changes on the air.

- **Setup page:** double-click `axlinkd` (or start it without arguments) and a page opens in the
  browser: callsign, radio, what runs on the radio and the address on the radio network, with a
  suggestion from the callsign. The station is stored, so `axlinkd run` needs no flags any more;
  `-call`, `-port` and `-ip` still override it. `axlinkd setup` opens the page again.
- **Linux service:** saving installs the systemd service `axlinkd` after one password prompt
  (pkexec). It runs as your user with `CAP_NET_ADMIN` and `CAP_NET_BIND_SERVICE` instead of as
  root, starts with the computer, and a start menu entry *AXLink* opens the web interface.
  `sudo axlinkd uninstall-service` removes it; the settings stay. Tested in CI and with the page
  in a browser; the service itself has not run on a real machine yet.
- **Windows and macOS:** the setup page starts AXLink with administrator rights (UAC prompt,
  password prompt). Not tested on a real PC or Mac yet.

Packages as before: Linux (amd64, arm64, armv6), Windows (amd64, arm64, with `wintun.dll`),
macOS (arm64, amd64), `SHA256SUMS`. Start: [QUICKSTART.md](https://github.com/TechnikWeber/AXLink/blob/v0.2.0-alpha.4/docs/QUICKSTART.md).
The programs are not signed. Use your own callsign; every operator is responsible for what is
allowed on their frequency.
